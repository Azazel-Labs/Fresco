# Particle art assets

## Individual torch particles

The [torch demo](../../50%29%20particles/torch.fr) uses these **512?512 RGBA**
sprites, each with one centered particle and a 32-pixel transparent border:

| Sprite | Use |
| --- | --- |
| [torch_flame.png](torch_flame.png) | Individual curling flame tongue |
| [torch_smoke.png](torch_smoke.png) | Soft turbulent smoke puff |
| [torch_ember.png](torch_ember.png) | Small elongated glowing ember |

These use straight alpha and alpha-over blending. Motion, birth variation, growth,
and lifetime fades come from the emitter and surface code. They have no baked
animation or torch geometry. Exact generation prompts: [torch-prompts.md](torch-prompts.md).

## Optional flipbooks

Three RGBA sprite sheets for particle demo experiments. Each is **1024×1024**,
with **16 frames in a 4×4 grid**. Cells are 256×256, with 20 transparent pixels
of padding on every side. Frame zero is at the top left; advance left to right,
then down. The pivot is the center of each cell.

| Sheet | Effect | Suggested playback | Suggested blending |
| --- | --- | --- | --- |
| [smoke_puff.png](smoke_puff.png) | Expanding gray smoke that dissipates into wisps; can be tinted | 12 fps, 1.33 seconds | Alpha over |
| [flame_burst.png](flame_burst.png) | Ignition, bright flame bloom, curling flame, final ember | 24 fps, 0.67 seconds | Alpha over or alpha-weighted additive |
| [spark_burst.png](spark_burst.png) | Radial flash, outward streaks, fading ember fragments | 30 fps, 0.53 seconds | Alpha-weighted additive |

These are one-shot sequences, not seamless loops. The timing and blending choices
are starting points for art tuning. Generated frames are not a physical simulation
or guaranteed optical-flow sequence; crossfade adjacent frames if useful.

The PNGs contain real transparent and partial-alpha pixels with straight
(unassociated) alpha. Use alpha to weight additive RGB; do not add unweighted RGB
from translucent glow pixels. If the render pipeline expects premultiplied output,
multiply sampled RGB by alpha in the shader. Decode color as appropriate for the
host's color pipeline, but do not gamma-decode alpha.

## Sampling

[sheets.json](sheets.json) records the frame layout and suggested playback. It is
asset metadata, not a new Fresco compiler or renderer manifest contract.

For a top-left texture-coordinate origin and `local_uv` in `[0, 1]`:

```text
frame = clamp(floor(age_seconds * fps), 0, 15)
cell = (frame % 4, floor(frame / 4))
pixel = cell * 256 + 0.5 + local_uv * 255
atlas_uv = pixel / 1024
```

If billboard UVs use bottom-left orientation, convert local Y to `1 - local_uv.y`
before applying this formula. The padding is part of the frame; sample the whole
cell. Fade out or retire the particle at the end of the sequence. Use clamp
addressing and linear filtering. Avoid full-atlas mipmaps that mix adjacent
frames; use LOD 0 or generate frame-isolated mip levels.

These optional sheets are not used by the torch demo. Integrating them requires texture binding, frame
selection from the available particle age/time, and compatible blending.

## Creation and checks

Created with the built-in image-generation tool; exact prompts are in
[prompts.md](prompts.md). The generated 4×4 sheets were split into equal cells,
resampled to 216×216 artwork, and packed into 256×256 cells. An eight-pixel
smooth alpha feather at each artwork boundary removes hard cuts where generated
wisps reached a cell edge. Alpha was preserved rather than keyed from a background.

All sheets were checked for dimensions, 16 populated frames, partial alpha,
transparent gutters, and appearance against a dark background. The playground
copy is generated by `node crates/fresco-wasm/web/scripts/sync-examples.mjs`.
